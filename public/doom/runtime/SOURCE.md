# Doom WebAssembly corresponding source

The committed `doom.mjs` adapter embeds the unmodified Emscripten JavaScript
loader from `danborden1/doom-web@e0ba81004e27e7d66141925dfebb091a558e2fe8` and adds the small
adapter generated by `scripts/build-doom-runtime.mjs`.

The engine files in that distribution are the published artifacts from:

- Deployment: https://github.com/Saketh-Chandra/doom-wasm-pwa/tree/5b1e1fe7385b6f0b19d60dece6adbf88f6842e20
- Corresponding source: https://github.com/Saketh-Chandra/doom-wasm-pwa/tree/a77edfd8bbc7e66b119a49c954f69a8b24e59206
- Original port: https://github.com/cloudflare/doom-wasm
- Engine lineage: https://github.com/chocolate-doom/chocolate-doom

Rebuild the upstream loader and WebAssembly with the exact source revision and
its `scripts/build.sh`, then run:

```sh
npm run build:doom-runtime -- \
  /path/to/websockets-doom.js \
  /path/to/websockets-doom.wasm \
  /path/to/default.cfg \
  /path/to/COPYING.txt \
  /path/to/DOOM1.WAD \
  /path/to/DOOM1-SHAREWARE.txt
```

The build command rejects inputs that do not match the reviewed upstream
artifact hashes before producing the public runtime.
